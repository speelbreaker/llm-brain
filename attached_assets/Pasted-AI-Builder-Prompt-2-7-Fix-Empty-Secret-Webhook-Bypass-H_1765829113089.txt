A) P0 CRITICAL: Never verify with an empty webhook secret

File: src/supervisor/app.py (and signature helper if needed)

Current behavior passes settings.github_webhook_secret or '' into verification. This is unacceptable.

Fix

In the /github/webhook handler, before reading/validating signature:

If supervisor isn’t ready (app.state.ready is False) OR webhook secret missing, return 503 with {ok:false,error:"misconfigured"}.

Do not call verify_signature at all.

In verify_signature(secret, body, header):

Require secret to be non-empty. If empty → return False.

Require header to start with sha256= and be correct length. If not → return False.

Result

Missing secret must never lead to a “valid” signature.

Tests

Route test: if secret missing → /github/webhook returns 503 (or consistent misconfig code) even if signature matches empty secret.

Route test: valid secret + valid signature → accepted (200/202).

Route test: invalid/missing signature → 401.

B) HIGH: Fix AsyncClient lifecycle (no leaks)

File: src/supervisor/telegram_notify.py

Right now _get_client() creates clients but closure isn’t guaranteed.

Fix Option (preferred)

Create one httpx.AsyncClient at startup and store it on app.state.http_client (or per-service clients):

app.state.telegram_http = httpx.AsyncClient(timeout=20.0)

app.state.github_http = httpx.AsyncClient(timeout=20.0)

Pass the client into TelegramNotifier / GitHubClient and reuse it.

Close clients in lifespan shutdown (await client.aclose()).

Alternative (acceptable)

Ensure every call site uses async with httpx.AsyncClient(...) as client: so it always closes. (Less efficient but safe.)

Tests

Not required to assert closure, but ensure code paths do not create new clients per request unnecessarily (basic unit-level sanity).
