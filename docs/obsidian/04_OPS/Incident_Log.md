# Incident Log

## Truth of what broke and why
- Document the incident title, severity, start/stop, root cause, and mitigation.
- Attach links to alerts or runbooks that were triggered.
- Always include a follow-up action and owner so the same issue does not recur.

## Process
1. Timestamp the incident as soon as it surfaces.
2. Update this file in real time if the incident is ongoing.
3. Once resolved, summarize the resolution and archive the entry if it is safe to do so.
